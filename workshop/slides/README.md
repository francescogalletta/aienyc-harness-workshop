# Workshop slides

`deck.html` is the deck for the session: one self-contained page. Open it in a
browser. It is built from `src/` by `build.py` (Python 3.11+, standard library
only, no network). The harness never uses this folder.

| Key | Does |
| --- | --- |
| Right arrow, Space, click on the right | Next step or slide |
| Left arrow, click on the left | Back |
| `F` | Fullscreen |
| `D` | Light or dark |
| `#12` at the end of the address | Open at slide 12 |

## Build

```
python workshop/slides/build.py              # deck.html + dist/deck.fragment.html
python workshop/slides/build.py --theme ink  # dist/deck.ink.html + dist/deck.ink.fragment.html
python workshop/slides/build.py --all        # every theme
python workshop/slides/build.py --check      # validate; exits 1 on problems
python workshop/slides/build.py --gallery --all   # dist/gallery.<theme>.html for every theme
```

`deck.html` is committed; `dist/` is not. The fragment is the form the hosting
page wraps (`<title>`, font `<link>`, one `<style>`, markup, one `<script>`).
Same sources give byte-identical output. Run `--check` before committing; it
also says when `deck.html` is out of date. The build's own tests:
`python -m pytest workshop/slides/tests -q`.

## Where things are

```

                       minutes, statement, "builds on" line

src/layouts/           layouts.toml (the vocabulary) + one template per layout;
                       blocks/ for the pieces of a statement slide
src/themes/*.css       looks: tokens only
src/styles/            tokens.css (default tokens), base.css, components.css
src/assets/            sketch.svg and qr.json (generated by tools/)
src/js/                confetti.js, deck.js, viz.js (concatenated into one script)
src/styles/viz.css     the visuals kit's look (only in builds that use it)
src/vendor/            Rough.js, anime.js, ECharts, each with LICENSE and VERSION
src/gallery/           the design-system gallery: sections, gallery.css, gallery.js

tools/                 sketch.py, qr.py, shoot.py (screenshots; optional)
```

## Edit a slide

Find the words with a search in `src/slides/`, change them, build. A slide is a
`[[slide]]` with an `id`, a `name` (used for the numbered comment), a `layout`
and that layout's fields. A statement slide is a list of blocks, top to bottom:

```toml
[[slide]]
id = "s-excited"
name = "Excited"
layout = "statement"
blocks = [
  { display = "I got excited about this one." },
  { sub = "I may have overdone it.", step = 1 },
]
footnote = { text = "* Possibly ADHD. Not a doctor.", step = 2 }
```

- `step = n` shows a thing at click n (`out`, `mute`, `strike`, `fill` likewise).
- In any text: `==trust==` is the trust accent; `[words]{aside step=3}` is a
  handwritten aside at click 3; `[words]{strike=2}` strikes them at click 2.
- Spacing between blocks is automatic (`[rhythm]` in `layouts.toml`); `gap = "l"`
  overrides it on a block when needed.
- Layouts, block roles and inline roles are all listed, with their fields, in
  `src/layouts/layouts.toml`. `raw` takes bespoke HTML when nothing fits.
- Slides are numbered by position; move one by moving its `[[slide]]`.
- A principle (name, emoji, minutes, statement) is one line in
  `principles.json`; the structure flow, the framework stack and its repeat,
  the rail and the dividers all follow.
- The sketch on "How we got here" is drawn by `tools/sketch.py`; the QR by
  `tools/qr.py` (needs `segno`; `--check` says when the QR is for another URL).

## Add a chart, diagram or animation

A visual is a block like any other: `{ viz = "<type>", label = "…", … }` in a
statement slide's `blocks`, or the `figure = { … }` of a figure slide. `label`
is required: it is what a screen reader hears, next to a hidden table of the
data. `step = n` is the click the data appears on; per-item steps are noted
below. `style = "rough"` draws any of them by hand; `animate = false` keeps it
still. `--check` rejects unknown keys, malformed data and steps out of order.

```toml
{ viz = "flow", label = "…", nodes = ["Ask", { text = "Plan", principle = 1 }, { text = "Check", role = "accent", step = 2 }], travel = 3 }
#   direction = "column" | "grid" (+ columns, at = [col, row] per node, links = [[1, 2], [1, 3]]); reveal = "each"
{ viz = "bars", label = "…", data = [["Jan 15", 18200], ["Jun 10", 9800]], highlight = "Jun 10", highlight_step = 2, prefix = "$" }
#   orient = "horizontal"; values = "all" | "none" | ["Jun 10"]; max, ticks, axis = false
{ viz = "waterfall", label = "…", start = ["Savings", 12000], changes = [["Gift", 5000], ["Venue", -3500]], end = "Left", reveal = "each" }
{ viz = "line", label = "…", x = ["Jan", "Feb", "Mar"], series = [{ name = "Plan", values = [1, 2, 3], step = 1 }], area = true, note = { at = "Feb", text = "dip", step = 2 } }
{ viz = "timeline", label = "…", events = [{ date = "2026-01-15", text = "Venue deposit", value = "$3,500" }], reveal = "each" }
{ viz = "count", label = "…", to = 11400, prefix = "$", step = 3 }
{ viz = "draw", label = "…", svg = "sketch.svg" }     # any SVG in src/assets: each [data-step] group strokes in at its click
{ viz = "echarts", label = "…", option = '''{ "xAxis": { … }, "series": [ … ] }''' }   # ECharts option as JSON
```

Two more work on any slide, as slide-level lists:

```toml
marks  = [ { target = ".display .hook", kind = "circle", step = 2, style = "rough", note = "here" } ]   # underline | circle | bracket | box
choreo = [ { step = 1, targets = ".pill", from = { opacity = 0, translateY = 60 }, to = { opacity = 1, translateY = 0 }, stagger = 90 } ]
```

`[words]{hook}` in any text makes a target for a mark. In `raw` HTML, write the
figure yourself: `<figure class="viz" data-viz="bars" data-spec='{…}'>`, plus
`data-lib="rough"` (or `echarts`) when it needs a library.

Colours, fonts, strokes and timings come from the `--viz-*` tokens at the end
of `src/styles/tokens.css`, mapped onto the theme's roles: a theme needs no
edits and may override any of them. Motion plays on a forward click only; going
back, arriving from the next slide, or reduced motion show the end state.

**Which tool.** The kit (`viz.js`, about 13 KB gzipped with its CSS and tokens)
covers the types above; reach for it first. On the shelf, inlined into a build
only when a slide asks for it:

- **Rough.js** (9 KB gz), `style = "rough"`: the hand-drawn look of the sketch.
- **ECharts** (234 KB gz), `viz = "echarts"`: data-heavy or unusual charts the kit
  does not draw (stacked, scatter, many series). It gets the theme's fonts,
  colours and series palette, and redraws when the theme changes.
- **anime.js** (40 KB gz), `choreo`: several elements moving in sequence on one click.

The build scans the rendered slides: `data-viz` pulls in the kit, `data-lib`
pulls in that library from `src/vendor/`, ahead of the deck's own script in the
same `<script>`. A deck with no visuals builds exactly as before.

## Review a variation

`python workshop/slides/build.py --gallery --theme NAME` (or `--all`) builds
`dist/gallery.NAME.html` and its fragment: the theme's colour roles and type
scale with live values, every layout, every component, and every visual in
clean and rough styles, on sample data. Press `D` for dark. Change a token,
rebuild, look. Screenshots for a side-by-side:
`python workshop/slides/tools/shoot.py shots dist/gallery.NAME.html dist/shots/gallery/NAME --set all --dark`.

## Change the look

Everything visual is a token. `src/styles/tokens.css` holds the defaults (type
scale, spacing, radii, strokes, motion, and the component tokens components
read). A theme sets the palette, fonts and colour roles, and overrides whatever
else it wants. Components never contain colours, font names, font sizes, radii,
paddings or gaps; `--check` enforces that.

- One knob for all type: `--type-scale` (in `tokens.css`, or override it in a theme).
- A role's size: e.g. `--display-size`, or the step it points to (`--fs-4xl`).

## Add a theme

Copy `src/themes/blueprint.css` to `src/themes/NAME.css` and change values. The
shape is:

```css
/* NAME: one line on the look.
   font-link: https://fonts.googleapis.com/css2?family=...
*/
:root { palette; --font-sans/mono/hand/emoji; colour roles (light); overrides }
:root[data-theme="dark"] { colour roles (dark) }
```

Write the dark values once; the build repeats them under
`prefers-color-scheme: dark` as the hosting page needs. Then
`build.py --theme NAME` and `build.py --check` (it lists missing tokens and
reports contrast; text on a principle fill must be at least 4:1).

`ink.css` (dark, high contrast, Space Grotesk, square) and `paper.css` (warm,
serif display, soft corners, thin strokes) are **examples** that show the range;
they are not design proposals.

## Look at it

`tools/shoot.py` (needs Playwright and Chromium) takes screenshots, compares two
sets with ImageMagick, and steps through every slide checking console errors,
the address, elements outside the 1920×1080 stage and phone-width scrolling:

```
python workshop/slides/tools/shoot.py shots deck.html dist/shots/blueprint --set review
python workshop/slides/tools/shoot.py check deck.html --csp     # with the hosting page's CSP
python workshop/slides/tools/shoot.py frames dist/gallery.blueprint.html dist/shots/frames --at 21:1
python workshop/slides/tools/shoot.py compare BEFORE_DIR AFTER_DIR
```

Where Google Fonts cannot be reached, pass `--font-dir` (or set `DECK_FONT_DIR`)
to a folder of the woff2 files listed in `tools/fonts.json`.

Dashed boxes are placeholders still to fill (`data-placeholder`).
